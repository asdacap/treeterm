# c11-preload_eventDispatcher

Verified: +2 rows, 8 rows changed

Architecture note: the preload script is the bridge between Electron's renderer and main
processes. Every `ipcRenderer` channel, listener list and `contextBridge` export is IPC plumbing
(NA in the port, which is one process). Each preload API row below maps the capability behind
it: daemon RPC passthroughs are SHARED (same RPC, called through `treeterm-core`), main-process
capabilities (dialogs, settings, clipboard, ssh/connection manager, menus) are mapped to their
Rust owner. The event dispatcher exists only because in Electron "start a command" and
"subscribe to its events" are two unordered IPC steps. In the port the call returns its event
stream (`Rt::subscribe` pumps into a bounded channel that queues items until polled), so early
events cannot be lost. Its user-visible guarantees are mapped row by row.

"Dead" below means the preload API has no consumer in `src/renderer` (or main never emits the
channel outside tests), so it has no user-visible behaviour to port.
