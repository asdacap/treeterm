# c71-shared_lifecycle

Verified: +12 rows, 15 rows changed

Scope: `src/shared/lifecycle.ts` (1-223), `src/shared/types.ts` (1-320), `src/shared/workspaceFavourites.ts` (1-50), `src/shared/workspaceFile.ts` (1-98), `src/shared/workspaceSettings.ts` (1-21).

Notes on approach: `lifecycle.ts` is a disposable/ownership toolkit. In the port, ownership and `Drop` replace it: gpui `Task`/`Subscription` and `treeterm_core::rt::{Fut, Sub}` cancel their work when dropped (`AbortOnDrop`, app-rs/crates/treeterm-core/src/rt.rs:71). Pure ownership mechanics are NA. The behaviours those mechanics guarantee (acquire-vs-dispose race, eviction, "dispose is not close") are mapped to the Rust code that provides them. Most of `types.ts` is type declarations. Each type maps to a Rust type, and comment-encoded defaults or constraints get their own rows. Where I checked a settings field's consumer and found it unused in the port, that row is PARTIAL even though the consumer belongs to another chunk.
