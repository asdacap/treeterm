Architecture note on the `if (!this.client) throw/return 'Not connected to daemon'` guards: Electron's `client` is nullable, while Rust's `DaemonConnection` exists only after `connect()` succeeded (one per connection generation). A call on a dead generation fails with `ApiError::Status` (the single-use connector in `transport.rs:40-44` refuses to redial). So the guards are NA. The calls themselves are mapped row by row.

## Gaps

- c05-48 PARTIAL (medium, Files/editor), src/main/grpcClient.ts:721: text reads decode UTF-8 lossily for every consumer. The Rust viewer, Comments, git diff sides and small text reads match. The Rust Editor tab reads the file again, decodes it strictly and refuses any non-UTF-8 file with "Binary files cannot be edited" (app-rs/crates/treeterm-model/src/text_editor.rs:173-179). Electron's editor takes the viewer's lossy text (FileViewer.tsx:476-487), so a Latin-1 or other non-UTF-8 text file with no NUL bytes opens and can be edited there; saving it replaces the invalid bytes with U+FFFD.
- c05-49 PARTIAL (medium, Files/editor), src/main/grpcClient.ts:723: `readLanguage` tags `.ico` and `.avif` as `image`, so Electron's viewer shows them as images. Rust's `presentation_of` (app-rs/crates/treeterm-model/src/file_browser.rs:106-121) has no ico or avif arm, so they show as a binary file. `content_kind::read_language` and `is_raw_bytes_path` (app-rs/crates/treeterm-core/src/files/content_kind.rs:101-116) include both but have no caller.
