# c19-renderer_components_CreateChildDialog-L455

Verified: +6 rows, 11 rows changed

Scope: `src/renderer/components/CreateChildDialog.tsx` lines 455-913: the Settings section, error and processing lines and action buttons of the "Add Child Workspace" dialog, plus the five list loaders (`ExistingWorktreesLoader`, `RecentWorkspacesLoader`, `LocalBranchesLoader`, `RemoteBranchesLoader`, `PullRequestsLoader`).

The Rust port is one view, `app-rs/crates/treeterm-app/src/child_dialog.rs` (`ChildDialog`). Its loaders are the `Mode` arms of `ChildDialog::load`, its rows come from `ChildDialog::rows`, and `ChildDialog::list` draws them. Unless a row names another file, `child_dialog.rs:<line>` refers to that file.

Two design differences behind most of the gaps:

- **No in-dialog processing state.** Electron's `isProcessing` is set only while `onAdopt` is awaited (Existing/Recent tabs, L122/L155). While it is set, controls are disabled, buttons read "... Please wait" and `processingMessage` is shown. In Rust, `SessionStore::adopt_worktree_with` (`app-rs/crates/treeterm-model/src/session_store.rs:1768`) returns the new id at once. `ChildDialog::started` (:527) then closes the dialog, and progress shows on the tree's Loading entry ("Opening worktree...", session_store.rs:1793).
- **Lists are cached per dialog, not re-fetched per mount.** Electron unmounts a loader when the user leaves its tab and remounts it on return: a fresh "Loading..." and fetch, with results from an unmounted loader dropped (`cancelled`). Rust's `ChildDialog::load` (:178-189) reads each tab's list once per dialog and applies any late result, including an error, to whichever tab is showing.

(v) Verification also found that the Settings section's custom default application is not applied when adopting a worktree from the Open Existing or Recent Workspace tab (c19-150), and added rows for keyboard reachability, the list box, row layout, second-line wrapping and selection under a search filter (c19-151 to c19-155).
