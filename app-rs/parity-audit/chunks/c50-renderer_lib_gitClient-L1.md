## Gaps

- c50-125, PARTIAL, src/renderer/lib/gitClient.ts:604: worktree-removal progress is not shown. During merge-and-remove Electron streams `$ git rev-parse ...`, `$ git worktree remove ... --force`, `$ git branch -D ...` and git's replies into the merge output pane; Rust's `remove_locked` passes `Progress::Silent`, so the pane shows nothing during cleanup, which can take minutes on large repos. Nearest: app-rs/crates/treeterm-model/src/session_store.rs:2315 (remove_locked), app-rs/crates/treeterm-core/src/git/mod.rs:706 (remove_worktree, progress supported). Severity medium (Git).
- c50-3, PARTIAL, src/renderer/lib/gitClient.ts:37: the exec backstop margin is 10 s in Rust, 5 s in Electron. A lost exec result times out 5 s later and the "timed out after Nms" figure is 5000 larger (40000 vs 35000 by default). On purpose (exec.rs:28: the daemon SIGKILLs 5 s after SIGTERM, which Electron's margin races), but not in the README. Nearest: app-rs/crates/treeterm-core/src/exec.rs:31 (EXEC_BACKSTOP_MARGIN). Severity low (Daemon client).
- c50-103, PARTIAL, src/renderer/lib/gitClient.ts:541: uncommitted-changes coalescing is per GitApi instance (one per Review tab, built by `DaemonConnection::git()`), not per session. Two Review tabs on the same repo each scan, and one Rust Uncommitted refresh runs two scans (content + overview) where Electron runs one. Performance only. Nearest: app-rs/crates/treeterm-core/src/git/mod.rs:1100 (get_uncommitted_changes), app-rs/crates/treeterm-core/src/daemon.rs:219 (DaemonConnection::git), app-rs/crates/treeterm-model/src/workspace_store.rs:776, app-rs/crates/treeterm-model/src/review.rs:950,1083.
