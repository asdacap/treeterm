# c02-main_connectionManager

Verified: +2 rows, 10 rows changed

Electron's `Connection` class (state, heartbeat, reconnect loop, logs, port forwards) and its `ConnectionManager` registry map to treeterm-core's `connection` module. The Rust version is split into three parts:

- `machine.rs` (`ConnectionMachine`) holds the state machine and does no I/O.
- `driver.rs` (`Shared`/`Hub` + `drive`) owns the transport, the heartbeat stream, the ssh processes and the log buffers.
- `manager.rs` (`ConnectionManager`) is the registry.

`manager_tests.rs` is a test-by-test port of Electron's `connectionManager.test.ts`, and `treeterm-testkit/tests/connection.rs` runs the manager against a real daemon. The app consumes all of this in `treeterm-model/src/app_store.rs`.

## Gaps

- c02-9, PARTIAL, src/main/connectionManager.ts:40: the per-connection byte counter does not survive reconnects in Rust. Each generation gets a fresh counter (daemon.rs:79), and each new `SessionStore` (app_store.rs:244) makes a fresh `TrafficMeter`. The session badge's total-received tooltip resets to 0 and the badge reads "↓ …" again until the first sample. Nearest: app-rs/crates/treeterm-core/src/daemon.rs:73 (DaemonConnection.received), app-rs/crates/treeterm-model/src/session_store.rs:401.
- c02-17, PARTIAL, src/main/connectionManager.ts:80: a Disconnected `ConnectionInfo` carries the last error in Electron; Rust's `ConnectionStatus::Disconnected` has none. Neither UI can show it, because both drop the connection's store or slot before or on Disconnected. Nearest: app-rs/crates/treeterm-core/src/connection/types.rs:83.
- c02-66, PARTIAL, src/main/connectionManager.ts:306: Electron logs "scheduling reconnect attempt N in Xms". Rust logs the loss and each failed attempt but not the scheduled attempt or its delay. Developer log only. Nearest: app-rs/crates/treeterm-core/src/connection/machine.rs:529.
- c02-83, PARTIAL, src/main/connectionManager.ts:398: if the old tunnel exits on its own while the connection is Reconnecting, Electron shows the tunnel's exit message as the Reconnecting error. Nearest: app-rs/crates/treeterm-core/src/connection/machine.rs:533.
- c02-113, PARTIAL, src/main/connectionManager.ts:542: `getByteCounter(connectionId)` returns a total that spans reconnects (and throws for an unknown id, which drives the badge's "↓ ?" error state). Rust only has the per-generation `DaemonConnection::received()`. Nearest: app-rs/crates/treeterm-core/src/daemon.rs:233.

Rust starts a fresh machine and counter, so the host's total resets after Retry, Refresh or Connect anyway. Nearest: app-rs/crates/treeterm-core/src/connection/manager.rs:161 (start).
