# c67-renderer_types_index

Verified: +1 rows, 21 rows changed

Electron file: `src/renderer/types/index.ts` (1-814). It holds renderer type declarations (tab state shapes, git/GitHub/review result types, the preload and client API interfaces) and a few runtime helpers (`isAppAvailableForConnection`, `bindConnectionId`/`createBoundFilesystem`, `getTabs`, and the state type guards).

How the port maps it:
- Tab state is untyped `serde_json::Value` with Electron's keys, created by `AppDef::initial_state` (`app-rs/crates/treeterm-model/src/apps.rs:127`) and read leniently by `WorkspaceStore::init_tab` (`app-rs/crates/treeterm-model/src/workspace_store.rs:695`). There is no shape validation, so the type guards' "reject" branches have no parallel (listed as benign PARTIAL rows).
- Git, GitHub, review and LLM result types are Rust types in `treeterm-core` (`git/types.rs`, `github/mod.rs`, `review/comments.rs`, `review/viewed_files.rs`, `llm/mod.rs`).
- For the preload and client API interfaces, each method is mapped to the capability in the port. Most preload methods were already audited method by method in c12 (`src/preload/ipc-client.ts`); those rows cite the c12 row. Where c12 found a difference in the handler behind the capability, the same PARTIAL is repeated here.
