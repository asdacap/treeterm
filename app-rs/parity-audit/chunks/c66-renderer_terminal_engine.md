# c66-renderer_terminal_engine

Verified: +12 rows, 13 rows changed

Scope: `src/renderer/terminal/{engine,ghosttyEngine,proposeDimensions,xtermCellSize,xtermEngine}.ts`, `src/renderer/types/classification.ts`.

Architecture note: Electron has two engines behind `TerminalEngine` (xterm.js + WebGL for `terminal` / AI-harness tabs, ghostty-web for the `ghostty-terminal` app). The port has one engine: `alacritty_terminal` driven by `treeterm-term::core::TermCore`, read through `treeterm-term::view`, owned by `treeterm-model::terminal::TerminalModel`, drawn by `treeterm-app::{terminal_view,terminal_element}`. `ghostty-terminal` is registered as an alias of the native terminal (`app-rs/crates/treeterm-model/src/apps.rs:434`), hidden from the new-tab menu, so only Ghostty tabs created by Electron reach it. OSC 52 decoding in the port is alacritty_terminal 0.26's `Term::clipboard_store` (vte 0.15 OSC parsing, `base64` STANDARD engine), filtered by `core.rs` `drain_events`.

(v) Verifier note: rows c66-139..150 map xterm.js 6.0 defaults that `createXtermEngine` leaves in place (it sets only cursor, font, scrollback, linkHandler and theme), because they decide what the user sees in Terminal and AI-harness tabs. Library sources checked: xterm.js 6.0.0 (`OptionsService.DEFAULT_OPTIONS`, `SelectionService`, `Linkifier`, `OscLinkProvider`, `Clipboard.ts`) and ghostty-web 0.4.0 `dist/ghostty-web.js`.
