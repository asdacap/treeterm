# c65-renderer_store_settings

Verified: +2 rows, 19 rows changed

This chunk covers four Electron files. The renderer settings store (defaults, load and save, the sound toggle, updateSetting) maps to `treeterm-core/src/settings/mod.rs` (the `Settings` type and its `Default`) and `treeterm-model/src/settings_store.rs` (`SettingsStore`). Application variants are registered by `treeterm-model/src/apps.rs` (`AppRegistry::from_settings`).

The workspace attention files map to `treeterm-core/src/attention.rs`. That file holds the metadata format, `AttentionSyncState` and `AttentionTracker`, the port of the coordinator's per-session `observe`. Its tests (`attention/tests.rs`) port the Electron tests one by one.

In production the tracker is owned per workspace by `treeterm-model/src/workspace_store.rs`, not per session by a renderer-wide coordinator. Session lifetimes come from `app_store.rs`: a session store is retired whenever the connection leaves Connected, and rebuilt on reconnect. The ding goes WorkspaceEvent::AttentionRecorded, then SessionEvent, then AppEvent::Attention, and `AppView` plays the system bell.

Main finding: `reconcile_write` is ported, but the model never registers its own writes and drops its own echoes before reconciling. Attention mutations committed by its own writes therefore stay pending (c65-121). (v) The second audit confirmed this and found a worse effect: with an earlier record and acknowledge still queued, the next external edit of the workspace clears Rust's own current unread marker. It also found that a failed settings save is never retried by pressing Save again (c65-90, c65-170).
